Session token stored in plaintext SharedPreferences
AuthManager.java · line 118 · MASVS-STORAGE-1
Critical
Agent explains
The token returned from /api/login is written directly to SharedPreferences with MODE_PRIVATE, which is readable on rooted devices or through a backup extraction. Anyone who recovers this value can replay it as an authenticated session until it expires or is revoked. Fix: store it in the Android Keystore-backed EncryptedSharedPreferences, and shorten token lifetime server-side.
Certificate pinning disabled in release build
NetworkModule.java · line 44 · MASVS-NETWORK-1
High
Agent explains
A build flag guards the pinning block and evaluates false in the release flavor, so the release APK trusts any CA in the system store. Combined with the plaintext token above, a MITM on public wifi is enough to intercept a live session, not just credentials in transit.

Security Assessment — com.northbank.mobile

v4.2.1 · Generated Jul 22, 2026 · Draft, AI-assisted

Executive summary

The assessment identified 12 findings across storage, network, and platform categories, including two critical issues that combine into a plausible account-takeover chain. We recommend resolving the token storage and certificate pinning findings before the next public release.

Key risk

An attacker positioned on the network can defeat certificate pinning, then recover the session token from local storage on a rooted or backed-up device, resulting in full session hijack without needing the user's password.

Any known CVEs for the OkHttp version this app bundles?
Agent · web research This build bundles OkHttp 3.12.1. That version has a known CVE around hostname verification bypass in certain proxy configurations, patched in later 3.12.x releases. Worth confirming the exact patch level and bumping the dependency regardless, since it lines up with the pinning finding above.
