## Scope (mirrors the M1 owner decision)

Engine + RQ job + CLI only. The HTTP upload/findings API stays in M5.

In scope: IPA unpack → Info.plist + entitlements + Mach-O static findings →
gitleaks enrichment → normalized findings persisted via the same schema as
Android. **Static-only is an explicit v1 constraint** (PRD §5.1): no Frida, no
jailbroken-device workflows, no dynamic confirmation of runtime behavior.

Out of scope: decompiling/recompiling iOS binary logic (that's M8, and
resource/plist-only there), runtime keychain/pinning behavior confirmation.

## Why the existing choices are right (from the tech stack doc + research)

- **LIEF, not otool/class-dump** — otool/class-dump are macOS-only binaries and
  would break the single-Linux-Docker-install requirement. LIEF is a
  cross-platform C++/Python library with manylinux wheels, Apache-2.0, and
  first-class Mach-O support (`lief.MachO.parse`).
- **Entitlements from the embedded signature blob, no `codesign`** — `codesign`
  is also macOS-only. LIEF exposes the code-signature blob directly; we carve
  the entitlements plist out of it and parse with `plistlib`.
- **Gitleaks reused as-is** — same wrapper as M1, different input surface
  (the unpacked `.app` tree instead of decompiled Java).

## Module layout (`backend/app/analysis/`)

```
analysis/
  base.py, severity.py, subprocess.py, mastg.py   # reused from M1 unchanged
  gitleaks.py                                     # reused as-is
  orchestrator.py                                 # + run_ios_analysis()
  ios/
    __init__.py
    ipa.py          # zipfile unpack -> Payload/*.app; bundle id/name; errors
    plist.py        # plistlib: ATS, usage strings, MinimumOSVersion, metadata
    macho.py        # LIEF: PIE/canary/ARC/encryption/symbols/dylibs/archs
    entitlements.py # carve code-signature blob + plistlib parse
```

`run_ios_analysis(ipa_path, work_dir)` parallels `run_android_analysis`:
preflight (valid zip with a `Payload/*.app`) → unpack → plist (required) →
Mach-O + entitlements (required) → gitleaks (enrichment). `ScanAborted`
policy and stage-warning collection copied from M1's orchestrator.

## Sequencing (dependency-ordered)

### Phase 1 — Foundation (no LIEF yet)
1. `ios/ipa.py`: unpack `.ipa` with `zipfile`, locate `Payload/*.app`, extract
   bundle id/name from the app's `Info.plist`; reject malformed archives with
   the same `ScanAborted` treatment M1 uses for non-APK files.
2. `ios/plist.py`: parse `Info.plist` in both binary and XML forms
   (`plistlib` handles both). Findings:
   - **ATS config** (`NSAppTransportSecurity`): `NSAllowsArbitraryLoads=true`,
     `NSAllowsArbitraryLoadsInWebContent`, broad `NSExceptionDomains` —
     `MASVS-NETWORK-1`-style categories.
   - **Missing usage-description strings** for sensitive APIs where the app
     declares the API (best-effort; informational).
   - **Bundle metadata**: `MinimumOSVersion`, `UIBackgroundModes`,
     `CFBundleIdentifier`/version (goes into `detail`, not as findings).
3. Platform autodetect: CLI `run`/`scan` and the orchestrator dispatch on file
   extension (`.apk` → android, `.ipa` → ios). `Scan.platform` already exists.

### Phase 2 — Mach-O + entitlements (LIEF)
4. Add `lief` to `requirements.txt` (pin latest stable at install time,
   ~0.16.x; Apache-2.0, manylinux wheels) + `docs/licenses.md` row.
5. `ios/macho.py` (main executable in `Payload/*.app/<Name>`):
   - **PIE**: `binary.header.has(FLAGS.PIE)` — finding when missing.
   - **Stack canary**: presence of the `___stack_chk_guard` symbol.
   - **ARC**: presence of ObjC runtime retain/release symbols
     (`objc_retainAutorelease` family) — best-effort indicator.
   - **FairPlay encryption**: `LC_ENCRYPTION_INFO`/`LC_ENCRYPTION_INFO_64`
     `cryptid != 0` → **informational finding** that static analysis coverage
     is limited (App Store binaries are encrypted; ad-hoc/resigned/test IPAs
     are not).
   - **Exported symbols**: count + notable ones (goes to `detail`).
   - **Linked dylibs**: list (goes to `detail`; notable/framework names
     surfaced).
   - **Fat-arch info**: architecture slices present (arm64 / armv7…).
6. `ios/entitlements.py`:
   - LIEF v0.15+ exposes a first-class `code_signature` object
     (`data`, `data_offset`, blob wrapper) — use it to get the signature
     blob, carve the entitlements section, `plistlib.loads` it.
   - Findings: the granted entitlement set goes into `detail`; flag notable
     ones (e.g. `get-task-allow` present in a shipping-ish artifact).
   - **Coverage limit, surfaced in output**: if the blob can't be carved or
     the binary is FairPlay-encrypted, emit an explicit note finding (not just
     a docs line) that entitlement extraction is best-effort for
     ad-hoc/resigned IPAs.

### Phase 3 — Findings + persistence (same schema as Android)
7. `static_only: bool = True` on the findings schema — `FindingOut`,
   `Finding` model, `FindingRead`, Alembic migration `0003_static_only.py`.
   Every iOS stage sets it explicitly; it's the mockup's "static-only" label
   wired to real data.
8. MASVS/MASTG mapping: the vendored `mastg_mapping.json` already includes iOS
   tests (the sync script parses `tests/` + `tests-beta/` front matter, which
   covers both platforms). Backfill `category` + `mastg_test_id` from the
   control→test reverse lookup exactly as M1 does. Add a sync-time note if any
   iOS finding type lacks a mapping.
9. Reuse `gitleaks.py` as-is against the unpacked `.app` tree. **Validate on
   Linux**: gitleaks is text-oriented; confirm how it treats Mach-O binaries
   (may need a `strings`-style pre-pass or accept partial coverage) and record
   the finding in the progress doc + license/limitations notes.
10. `run_ios_scan(scan_id)` RQ job (parallel to `run_android_scan`), CLI
    `run`/`scan` handling `.ipa`.

### Phase 4 — Validation
11. **Unit tests** (no real IPA needed):
    - `ipa.py` unpack with a fixture `.ipa` built in-test (zipfile).
    - `plist.py` with synthetic binary/XML plists (binary form can be produced
      with `plistlib.dumps(..., fmt=FMT_BINARY)`).
    - `entitlements.py` carving with a synthetic signature blob.
    - `macho.py`: LIEF can *build* Mach-O files (`lief.MachO.Builder`) — use a
      builder-generated fixture rather than hand-rolled bytes.
12. **Integration test** against a pinned vulnerable sample IPA:
    - Primary candidate: **iBugBazaar** (`MASTG-APP-0030`,
      `payatu/iBugBazaar`) — actively maintained, 20+ deliberate vulns,
      prebuilt `.ipa` on the GitHub Releases page. Pin the release artifact
      + sha256 in the docs.
    - Fallbacks: DVIA-v2 (`MASTG-APP-0024`), OWASP iGoat-Swift
      (`MASTG-APP-0028`).
    - Confirm LIEF parses the sample on the **Linux host** first (the
      original PRD risk: don't assume macOS-only success carries over).
13. **Containerized e2e** (mirror M1): rebuild the image with `lief`, run the
    iOS pipeline inside the container, enqueue an iOS scan through the compose
    worker, verify `status=done` + findings persisted.
14. Docs: `docs/licenses.md` (+lief, +sample app note), `docs/progress/M2.md`
    status flip, `docs/masa-tasks.md` checkboxes.

## Decisions to confirm with the owner at implementation time

1. **Sample IPA choice** — iBugBazaar is the recommendation (active + prebuilt
   IPA); DVIA-v2/iGoat-Swift as fallbacks. Confirm the preferred one and that
   vendoring the IPA in-repo (like `InsecureBankv2.apk`) is acceptable.
2. **LIEF version pin** — propose latest stable at install (~0.16.x), pinned
   in `requirements.txt` like everything else.
3. **`static_only` as a column vs. computed** — plan is a real column with
   default True (dashboard filters on it); cheapest and matches the mockup.
4. **gitleaks on binaries** — if Linux binary scanning proves noisy, scope it
   to bundled resources + a `strings` pre-pass rather than raw binaries.

## Named risks / coverage ceilings (be honest in the UI)

- **FairPlay-encrypted App Store binaries** limit LIEF static analysis to
  headers/strings; deep symbol/entitlement reads may be partial. Test IPAs are
  unaffected. Surfaced as an informational finding when `cryptid != 0`.
- **Entitlement carving is best-effort** for unusual/adhoc signatures — noted
  in finding output, not just docs.
- **Static-only ceiling (product-wide):** runtime classes (keychain misuse,
  SSL-pinning behavior) can't be confirmed statically — v1 UI must not imply
  dynamic confidence.
