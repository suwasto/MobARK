# M3 — Model Backend Abstraction: Plan + Delivery

**Status: COMPLETE (Aug 5, 2026).** This doc records both the plan (written
after M2 shipped) and what actually landed. M3 mirrored M1/M2's shape —
engine + API surface + CLI only, same validation loop (host → container) —
applied to the AI connectivity layer: LiteLLM as the model client, a config
layer for swappable backends, health checks, and (originally) the ChromaDB +
embeddings foundation.

**Scope change at kickoff (owner decisions below):** the ChromaDB + embeddings
foundation was deferred to M4, so M3 shipped the model-backend layer only.

---

## Scope (mirrors the M1/M2 owner decision)

Engine + RQ job + CLI only — with one addition: M3 exposes the **API
endpoints** the Settings modal will consume, since the M3 checklist items that
say "in the UI" (model-pill status dot, backend cards' "Test" button) cannot
be a real React surface yet — the frontend isn't scaffolded until M5.

Delivered:

- **LiteLLM client wrapper** — `chat()` behind one module, replacing the
  hand-built OpenAI-compatible client class the PRD originally described.
  `embed_texts()` lands with M4's vector work.
- **Local backends** — Ollama (`localhost:11434` / `host.docker.internal:11434`
  in-container) and LM Studio (`localhost:1234/v1`), both OpenAI-compatible.
- **BYOK providers** via LiteLLM — curated v1 set (OpenAI, Anthropic, DeepSeek,
  OpenRouter) + a base-URL-only `custom` kind, backing the Settings modal's
  BYOK tab; key-required vs base-URL-only confirmed per provider.
- **Config layer** — switching base URL/model with no code change; seeded from
  `MASA_*` env vars, runtime-editable via the API (JSON store in `data_dir`,
  `0600` perms).
- **Connection health check** — exposed as API endpoints now, wired to the
  model-pill dot / Test buttons in M5.
- **Host + container validation** mirroring M1/M2.

Deferred (owner decision): ChromaDB + embeddings foundation → M4 (M4's
checklist now opens with the vector foundation pulled from M3's original Phase
4).

Out of scope (unchanged): RAG chunking/retrieval/chat (M4), React wiring (M5),
tool calling (M6), edit & recompile (M8).

## Decisions confirmed with the owner at implementation time

1. **BYOK key storage** — plaintext JSON in `data_dir` with `0600` perms;
   encryption-at-rest deferred to M5 (already an M5 checklist item). Keys are
   never logged (excluded from the dataclass repr) and never returned by the
   API (only `has_api_key`).
2. **Provider subset** — curated set of 4 (OpenAI, Anthropic, DeepSeek,
   OpenRouter) + `custom`, not all eight; the table lives in one module
   (`model/providers.py`) so the rest are trivial to add later.
3. **Default chat model** — no hard default: `model` seeds blank; the user
   picks from what the backend actually serves (`MASA_DEFAULT_CHAT_MODEL` can
   seed a concrete default).
4. **Embeddings in M3** — deferred to M4.

## Why the existing choices are right (from the tech stack doc + research)

- **LiteLLM (MIT), not a custom client class** — LiteLLM already normalizes
  Ollama, LM Studio (OpenAI-compatible), OpenAI, Anthropic, DeepSeek, and
  OpenRouter behind one interface, including consistent function-calling
  schemas where providers support them. Writing that abstraction from scratch
  means re-solving a problem LiteLLM already maintains against provider API
  drift.
- **Local servers need no real key** — `completion(model="ollama/qwen2.5",
  api_base="http://localhost:11434", api_key="ollama")` works with a dummy
  key; LM Studio likewise via the `openai/` prefix + dummy key. BYOK providers
  use standard env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, …) and
  provider-prefixed model strings (`openrouter/anthropic/claude-3.5-sonnet`).
- **Health check = cheap completion** — a `max_tokens=1` completion is the
  reliable runtime usability probe; the OpenAI-compatible `GET /models`
  listing (which both local servers and most BYOK providers expose) is the
  fast reachability signal. Anthropic has no OpenAI-compatible listing, so it
  carries a small static fallback model list and is verified by probe only.
- **ChromaDB (Apache-2.0), embedded mode** — deferred to M4, unchanged.

## Module layout (shipped, `backend/app/`)

```
model/
  __init__.py   # litellm tuning (drop_params, quiet errors)
  providers.py  # provider table: prefixes, env vars, key posture, listing paths
  backends.py   # ModelBackend + JSON config store (env-seeded, 0600, upsert)
  client.py     # chat() over litellm.completion (embed_texts -> M4)
  health.py     # check_backend + list_models (graceful, never raises)
vector/         # M4
```

Plus:

- `Settings` env defaults: `MASA_OLLAMA_BASE_URL`, `MASA_LM_STUDIO_BASE_URL`,
  per-provider `MASA_*_BASE_URL` / `MASA_*_API_KEY`, `MASA_DEFAULT_CHAT_MODEL`
  (blank by default).
- `api/routes/models.py` mounted at `/api/v1/model/*`:
  - `GET /api/v1/model/backends` — config + lightweight reachability (parallel
    model listing, no probe)
  - `POST /api/v1/model/backends/{id}/test` — full check incl. completion probe
  - `GET /api/v1/model/backends/{id}/models`
  - `PUT /api/v1/model/backends/{id}` — runtime upsert (base_url/model/key/enabled)
- `docker-compose.yml`: `extra_hosts: ["host.docker.internal:host-gateway"]` on
  app + worker, `MASA_OLLAMA_BASE_URL` / `MASA_LM_STUDIO_BASE_URL` pointed at
  `host.docker.internal`.

## Delivery notes / validation results (all run Aug 5, 2026)

**Unit tests (no network): 47 new tests** — config store round-trip,
env-seeding, 0600 perms, key redaction, corrupt-store reseed, client model
string mapping (ollama/ vs openai/ prefixes, BYOK, custom raw), `chat()`
kwarg passthrough, health behavior (live / unavailable / suggested sources,
probe success-failure, never-raises contract, lightweight no-probe), provider
table invariants, API surface (redaction, 404s, upsert persistence). Full
suite: **106 passed, 13 deselected (integration)**; `ruff check` clean.

**Host CLI e2e** (`python -m app.cli model health`): clean per-backend
results with servers absent — Ollama/LM Studio → `unreachable` (Connection
refused); OpenAI/DeepSeek → `unreachable` (401 — key not set); Anthropic →
probe attempted against static suggestions, failed keyless; OpenRouter →
`reachable` (public model listing, 338 models) with honest failed probe.
Store seeded at `data/model_backends.json` with `-rw-------` (0600).

**Containerized check** (compose build + one-off `docker compose run`):
image builds with litellm; `host.docker.internal` resolves (Docker Desktop
gateway); in-container `model health --backend ollama` hits the
`host.docker.internal` URL and reports graceful `unreachable` (Ollama not
running on the host — expected; goes green once `ollama serve` + `ollama pull
nomic-embed-text` are up). App boots in-container, 12 routes.

**Image size:** litellm is a chunky dependency — ~250–300 MB in
site-packages (litellm 128M + jedi/openai/networkx/hf_xet/tokenizers et al).
`docker images` reports masa-app 2.16 GB (vs the M2-era worker build at
1.73 GB). M1's 350–450 MB "content" gate was M1-specific and not re-stated
for M3; the size impact is documented here for M10 packaging decisions.
Also fixed a pre-existing `.dockerignore` bug this milestone: `data/` only
matched the repo-root dir, so `backend/data` (62 MB) was baked into images;
now `**/data`.

## Named risks / coverage ceilings (be honest in the UI)

- **Ollama/LM Studio not running on the host** — health check reports
  "unreachable" cleanly (red dot), never crashes a request or scan. Verified
  live on the host (servers down) and in-container.
- **`host.docker.internal` on Linux** requires the compose `extra_hosts`
  entry; behavior differs on Docker Desktop (macOS/Windows) — verified on
  macOS Docker Desktop.
- **Embedding model must exist on the host** — M4 concern: `nomic-embed-text`
  needs a one-time `ollama pull`; surface a clear error until then.
- **LiteLLM version drift** — provider env-var names and model-string formats
  shift; pinned at install (1.95.0) and the provider table lives in one module.
- **BYOK means data leaves the machine** — the config carries `kind`/`local`
  so M5's "Local-only" indicator can flip off the moment a BYOK backend is
  enabled.
- **Anthropic has no OpenAI-compatible model listing** — its model list is a
  small static fallback in the provider table (drifts; update in place); live
  reachability for Anthropic relies on the completion probe.

## How to run

```bash
# Host
ollama serve                # must already be running
ollama pull nomic-embed-text
cd backend && .venv/bin/python -m app.cli model health --backend ollama

# Compose (container reaching host via host.docker.internal)
docker compose build app    # then `docker compose up -d` to roll the new image
docker compose run --rm --no-deps app python -m app.cli model health --backend ollama

# API surface (what M5's Settings modal will call)
curl localhost:8000/api/v1/model/backends
curl -X POST localhost:8000/api/v1/model/backends/ollama/test
```
