# M4 — Agent Context Layers (Layers 1-3, no RAG): Plan + Progress

Written Aug 5, 2026 (original plan) · **REVISED Aug 6, 2026 — RAG deleted from v1**.

## Decision: delete RAG/embedding, replace with three non-embedding layers

The original M4 plan was a RAG chat MVP (ChromaDB + LlamaIndex CodeSplitter +
nomic-embed-text via Ollama) with a Graphify code graph alongside. Real
validation killed the RAG half:

- **Embedding on CPU is too slow to be usable.** Real numbers (InsecureBankv2,
  3 MB APK): 23,958 chunks, ~39 chunks/s ≈ **5-15 minutes of indexing before
  chat is even usable** — the bottleneck is embedding, not chunking (5.5 s) or
  graph build (1m17s).
- **Owner decision (Aug 6, 2026): delete the RAG/embedding pipeline entirely
  from v1 — not defer it.** Chunking code, ChromaDB setup, the embedding job,
  and the vector-retrieval chat endpoint were removed outright (no deferred
  folder, no commented-out code). `chromadb` and `llama-index-core` were
  uninstalled; `embed_texts()` deleted; migration `0004_index_state.py`
  removed (head back to `0003`). Verified zero leftover references in code
  paths (imports/config/tests).

Replacement: three non-embedding layers, all deterministic data/text/graph
operations:

| Layer | What it is | Platforms |
|---|---|---|
| 1 | Full findings set as direct agent context — every source, precision-tagged | Android + iOS |
| 2 | `search_code(pattern, glob)` + `read_file(path, line_range)` agent tools | Android + iOS |
| 3 | Graphify code graph (`extract --code-only` → `query`/`path`/`explain`) as agent tools | Android only |

### What RAG would still answer that Layers 1-3 can't (flagged, not re-introduced)

One genuine gap: *imprecise semantic recall* — "which parts of the app touch
user credentials" when you don't know an identifier, file, or finding to start
from. Layers 1-3 answer every identifier-shaped and findings-shaped question
deterministically and faster; fuzzy open recall is the sole loss, judged not
worth 5-15 min of CPU indexing per 3 MB APK.

## Layer 1 — structured findings as direct agent context

**Normalization.** Every analysis source already emits the unified `FindingOut`
shape into the `findings` table (M1/M2). `agent/context.py` adds the Layer 1
normalizer:

- **Precision derivation** (`derive_precision(tool)`): `[file/line]` for
  semgrep, gitleaks, androguard (manifest), plist (Info.plist); `[binary-level
  presence only, no specific location]` for lief (Mach-O protections /
  entitlements) and the import-table scanner. Rendered per-finding with a
  legend so the agent never conflates "found at line 42" with "binary imports
  it somewhere".
- **Platform tool whitelists**: Android = androguard/semgrep/gitleaks; iOS =
  plist/lief/symbols/gitleaks/semgrep. **androguard can never appear in an iOS
  context.**
- **Full set, no subsetting**: all findings rendered; `max_findings` is an
  explicit escape hatch, never a silent default.

**iOS sources made first-class (the named tool list, replacing vague
"LIEF-derived findings"):**

1. **Info.plist** (`plist` tool) — ATS config, usage strings (M2).
2. **Mach-O protections + entitlements** (`lief` tool) — PIE, stack canary,
   ARC, FairPlay (M2) + **binary profile info findings** added in M4 so the
   agent sees what `result.meta` previously hid: exported symbols, linked
   dylibs, architectures, ARC state, and the **full entitlement set** (the
   answer source for "what entitlements does this app have").
3. **Import-table scanner** (`symbols` tool, `analysis/ios/symbols.py`) —
   known-insecure API blocklist matched against Mach-O imports: `CC_MD5`,
   `CC_SHA1`, `CC_DES`, `CCCrypt` (legacy crypto; findings note that ECB-mode
   constants are code-level and not import-detectable), `UIWebView`,
   `NSURLConnection` cert-bypass selectors (`setAllowsAnyHTTPSCertificate`,
   `canAuthenticateAgainstProtectionSpace`), and `ptrace`/`sysctl`/`syscall`
   anti-debug. Pure matcher (`match_imports`) separated from the LIEF read.
   Binary-level precision by design.
4. **Gitleaks** — secrets + string scanning over the bundle, now with a custom
   iOS ruleset (`resources/gitleaks_ios.toml`): the `kSecAttrAccessibleAlways`
   insecure-keychain string is **string-level, so it goes through Gitleaks,
   not the import-table scanner** (as the owner specified).
5. **Semgrep** — included for completeness, **zero yield by design** (binary
   structure via LIEF, no decompiled Swift/ObjC source). The Layer 1 context
   builder flags it so the agent never leans on it.

## Layer 2 — grep + file read as agent tools (no platform branching)

`agent/tools.py`:

- `search_code(scan_id, pattern, glob="**/*", max_hits=100)` → `[{file, line,
  snippet}]` — regex over the scan tree, binary files skipped, results capped.
- `read_file(scan_id, path, line_start=None, line_end=None)` — path-traversal
  guarded, binary plists decoded via plistlib, other binary files refused with
  a clear message.

The tools contain zero platform branching — only `resolve_tree_root` knows
whether the tree is Android jadx output or an iOS `Payload/*.app` bundle.

## Layer 3 — Graphify as agent tools (Android only)

- `graph_query(scan_id, question, budget=1500)`, `graph_path(scan_id, a, b)`,
  `graph_explain(scan_id, node)` wrap `app/graph/graphify.py` (package renamed
  from `app/vector` — no "vector" name remains).
- `build_graph_scan` RQ job chained after `run_scan` (Android-only; iOS records
  `ios-no-source`). Graph state is **filesystem-derived** (`data/graphs/<id>/
  graphify-out/graph.json` + streamed node/edge counts) — no DB columns, no
  migration.
- Graphify output is **excluded from Layer 1** — it is an on-demand Layer 3
  tool, never pre-loaded findings context.

### Graphify CLI corrections (validated on 0.9.32)

- No `extract`/`export` subcommand — the headless code-only build is
  `graphify update <dir> --no-cluster` (cwd = per-scan graph dir).
- Queries via `graphify query|path|explain|affected --graph <path>`.
- Natural-language queries fail on code-only AST graphs (identifier labels
  only) → wrapper has a deterministic label/ID substring-search fallback.
- **iOS negative confirmed**: unpacked `.app` has 0 source-like files →
  Graphify is Android-only in v1.
- Real numbers (InsecureBankv2): 46,177 nodes / 116,780 edges / 64 MB
  graph.json, zero LLM, ~1m17s.

## Agent chat (bounded tool loop, zero embeddings)

`agent/chat.py`: assembles the Layer 1 context (full set), then runs a
bounded tool-calling loop (≤3 rounds) over the Layer 2/3 tools. Chat model
comes from the M3 backend store (no hard default). Models that don't emit tool
calls get a context-only answer — the documented graceful fallback.

API: `POST /scans/{id}/chat` restored with Layers 1-3 semantics (same response
shape as the deleted RAG endpoint, so M5's chat panel contract doesn't churn).
`GET /scans/{id}/graph` reports graph state. CLI: `graph build|query|path|
explain` + `agent context|chat` (`agent context` renders the exact Layer 1
context with zero LLM).
