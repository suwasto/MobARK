### 2.2 Risk score (single source of truth in the backend)

New `app/analysis/risk.py::compute_risk_score(findings) -> int`:

- weights: critical=10, high=7, medium=4, low=1, info=0
- `n` = count of findings with severity != info; `raw = Σ weights`
- `score = min(100, round(100 · raw / (10 · n)))` when `n > 0`, else 0
- Sanity: the mockup's illustrative 2C/4H/5M/1L → 58/100 ("High risk") — the
  mockup's 67 was decorative; our formula is deterministic and documented.

Computed in `run_scan` (after findings persist, before `status=done`), stored
in `Scan.risk_score`. `GET /scans/{id}` backfills when null (legacy scans).

### 2.3 Decompiler file tree (bounded)

- Android: two roots under `data/work/<id>/decompiled/` — `sources/` (jadx
  Java/Kotlin) and `resources/` (AndroidManifest.xml, res/…).
- iOS: the unpacked `Payload/*.app` bundle tree — **curated to text-readable
  files only**, with the hidden binary blobs grouped into a collapsed
  **`Binary (Mach-O)` (n) tree entry** (each listed inline with its full
  path; inert dimmed rows via the `FileNode.binary` flag — the count note
  was replaced by this inline listing) **plus a synthetic `analysis/` root**
  generated from the persisted binary-level findings:
  `macho-profile.md` (architectures, PIE/canary/ARC/FairPlay with honest
  "not flagged" phrasing, linked dylibs), `entitlements.plist` (full carved
  set as JSON), `exported-symbols.txt`, `insecure-imports.txt`. No Swift/
  ObjC source exists for iOS in v1 (Mach-O — no jadx equivalent; real
  decompilers are out of the image/licensing gates); this is the
  analyzed-bundle view the owner chose at Phase-F follow-up.
- Caps per root: max depth 8, max 1 500 nodes, `truncated: true` when capped.
  The UI lazy-expands client-side; no per-request expansion calls in v1.
- Content: cap 200 KB display read with `truncated` flag; binary sniff +
  plist decode via the existing `agent/tools.py` guards (shared helper, no
  duplicated traversal logic).

## 3. Frontend architecture (React 18 + TS + Vite + Tailwind v4)

### 3.1 Design system — Tailwind v4 CSS-first

Tailwind v4 has no `tailwind.config.js` by default — the "config" is a
`@theme` block in `src/index.css`, which is exactly where the mockup's tokens
land (this is the modern reading of the task-list line "port the design tokens
into a Tailwind config"):

```css
@import "tailwindcss";
@theme {
  --color-graphite: #14171a;   /* bg */        --color-panel: #1b2025;
  --color-panel-raised: #20262c;               --color-line: #2b3238;
  --color-line-soft: #242a30;  --color-bone: #e8e6df;
  --color-bone-dim: #9ba3a9;   --color-bone-faint: #6c747a;
  --color-steel: #5c9bb8;      --color-steel-dim: #3e6e85;
  --color-amber: #d98e3e;      --color-crimson: #c1554a;
  --color-moss: #6b8f71;
  --font-sans: "IBM Plex Sans", sans-serif;
  --font-mono: "IBM Plex Mono", monospace;
}
```

- Deps: `tailwindcss` + `@tailwindcss/vite` (vite.config plugin), fonts via
  **`@fontsource/ibm-plex-sans` + `@fontsource/ibm-plex-mono`** (bundled
  locally — no Google Fonts CDN, keeps the local-first posture honest),
  **highlight.js** (BSD-3-Clause) for Java/XML tokenization in the code viewer.
- Custom bits the mockup needs beyond utilities (kept as small CSS additions):
  scrollbar styling, the gauge arc (inline SVG + stroke-dasharray), the
  pulse-ring animation, code-line flagged styling, dropdown positioning.

### 3.2 Structure

```
frontend/src/
  main.tsx / App.tsx          # view machine: empty | progress | loaded
  index.css                   # @import tailwindcss + @theme tokens + custom css
  types.ts                    # TS mirrors of backend schemas (ScanRead, FindingRead, …)
  api/client.ts               # typed fetch client (base '/api/v1', JSON + multipart)
  state/AppContext.tsx        # light context: scans, activeScan, backends, actions
  hooks/
    useScanPolling.ts         # 2.5 s interval while status ∈ {queued, running}
    useFindings.ts / useExplain.ts / useChat.ts / useBackends.ts / useFileTree.ts
  components/
    TopBar.tsx                # brand, LocalOnlyBadge, ModelPill, Export (M9, disabled), +New scan, ⚙
    ModelPill.tsx             # dropdown: backends × served models, set default (PUT)
    TargetBar.tsx             # active scan identity + SwitchScan dropdown
    EmptyState.tsx            # dropzone + setup checklist (health + model status)
    UploadDialog.tsx          # file input → POST /scans → select scan
    ProgressScreen.tsx        # indeterminate bar + pipeline stage list (Scan.stage)
    Dashboard.tsx             # header/tabs + panels + AgentDock
    panels/OverviewPanel.tsx  # RiskGauge, stat boxes, AI summary (POST summary)
    panels/FindingsPanel.tsx  # filter chips + FindingCard (expandable explain)
    panels/DecompilerPanel.tsx# FileTree + CodeViewer + AnnotationRail
    panels/DependenciesPanel.tsx  # placeholder (M7)
    panels/ReportPanel.tsx        # placeholder (M9)
    code/FileTree.tsx / CodeViewer.tsx / AnnotationRail.tsx
    agent/AgentDock.tsx       # chat messages, citations, source chips (POST /scans/{id}/chat)
    settings/SettingsModal.tsx   # tabs: Backends / BYOK / Search (M7 placeholder)
```

- **No router**: single dashboard, tab state is local state (matches the
  mockup; the tech-stack doc already rejected SSR/routing complexity).
- **Active scan id** persists to `localStorage`; view machine derives from the
  active scan's status — no scans → `empty`, queued/running → `progress`,
  done/failed → `loaded`.
- **Local-only indicator** is derived, not decorative: green "Local-only" while
  every enabled backend has `local: true`; flips to amber/`via cloud` the
  moment any enabled BYOK/custom backend exists (and vice versa).
- **CodeViewer**: highlight.js tokenizes the file once; each rendered line
  carries a number, flagged state (from findings with `file_path`+`line`),
  and click-to-expand annotation; the AnnotationRail shows findings for the
  open file ordered by line, each expandable via the explain endpoint.
- **AgentDock**: messages from `POST /scans/{id}/chat`; citations render as
  file:line chips, `sources` as the mockup's `src-chip` row; graceful error
  states for 400 (no chat model) / 409 (not analyzed) / 504 (agent timeout);
  research toggle disabled until M7.

## 6. Decisions & open items

- **Risk formula** is a documented v1 heuristic (2.2); refine later if it
  misleads. Single source in `app/analysis/risk.py` so Overview and report
  export agree.
- **Explain/summary caching** on-row (migration 0004) — simple, survives
  restarts, no separate cache infra.
- **Encryption-at-rest for BYOK keys**: stays at the existing `0600` plaintext
  posture for v1 (single-user local tool, M3 owner decision); flagged as an
  optional stretch inside M5, defaulting to no change.
- **BYOK "Remove"** semantics: custom backends are deleted; seeded providers
  have the key cleared and `enabled=false` (they re-appear in the list as
  unconfigured, matching the mockup's provider cards).
- **File-tree caps** (2.3) keep large jadx trees (thousands of files) cheap;
  `truncated` is surfaced in the UI.
- **Progress screen** is real but coarse: `Scan.stage` is a human-readable
  stage string, not a percentage; the bar animates while `running`.
- Manual QA with a real model remains an owner checkpoint (mirrors M4's
  go/no-go), listed in the M5 checklist as the final item.
