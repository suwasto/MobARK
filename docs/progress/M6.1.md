# M6.1 — Dev-Only Fake LLM (demo the Agent dock without Ollama): Plan + Progress

Written Aug 9, 2026 · **STATUS: COMPLETE (Aug 9, 2026).** Owner request: a
small dev-only mock so the dock's live tool steps + token streaming can be
demoed and visually verified with zero Ollama. Built as a **backend-level
fake that runs the REAL agent loop + REAL tools** — not a frontend stunt
double — so the demo exercises the actual SSE protocol, the tool-call
accumulation path, and the citation jumps.

## Build notes (Aug 9, 2026)

- **Config knob:** `MASA_FAKE_MODEL=1` (`Settings.fake_model_enabled`,
  default **off**). Off = the fake never appears anywhere — no provider
  surface, no store entry, no production-path change. Existing store tests
  stay hermetic (verified: the pre-existing `{"ollama", "lm-studio"}`
  seed assertions still pass unchanged). **Live-verified env-alias bug
  (Aug 9)**: pydantic-settings derives env names from FIELD names, so
  `fake_model_enabled` silently became `MASA_FAKE_MODEL_ENABLED` — the
  documented `MASA_FAKE_MODEL=1` was ignored and the server started with
  the knob off. Fixed with an explicit `validation_alias="MASA_FAKE_MODEL"`
  (the raw alias IS the env name in pydantic-settings; the MASA_ prefix is
  not re-applied) + regression test. This is exactly why the live demo run
  mattered.
- **Provider + store:** a dev-only `fake` provider (`providers.py`, kind
  `local`, no base URL, `models_path=None` → static `demo` model) is seeded
  FIRST into the M3 store when the knob is on, so `pick_chat_backend`
  resolves it deterministically — chat, explain, and summary all demo
  against it without touching a real model. `BackendStore.read()`
  reconciles the entry with the knob (`_reconcile_fake`, idempotent, both
  directions) so flipping the env var on an EXISTING store converges
  without deleting `model_backends.json`. Single construction site
  (`backends.py::_fake_backend`) shared by seeding + reconcile so the two
  can't drift (review catch).
- **Short-circuit:** `model/client.py::chat` / `chat_stream` route
  `provider_id == "fake"` to `app/model/fake.py` (never touches litellm);
  `health._probe_completion` also short-circuits so the Settings card
  renders green with the `demo` model.
- **The script (`app/model/fake.py`, deterministic, real data):**
  - *Round 1:* streams a little thinking-aloud text, then emits two tool
    calls — `search_code` (pattern `WebView`, with the arguments split
    across **two streamed deltas** on purpose, so the demo exercises
    `_accumulate_tool_call_deltas`' concatenation exactly like a real
    local server) and `read_manifest`. Both EXECUTE for real, so the dock
    shows real hit counts.
  - *Round 2:* composes the final answer from the REAL tool results — it
    cites the actual first search hit (`file:line` → clickable src-chip
    that jumps the Decompiler tab) when one exists, or summarizes the
    manifest otherwise. A failed tool (`{"error": ...}`) is never mistaken
    for manifest data (review catch).
  - Calls without a `tools` kwarg (insights explain/summary, the
    plain-chat fallback) get a canned plain answer.

## Known edges (deliberate)

- The knob ON **shadows real backends** (`pick_chat_backend` resolves the
  seeded fake first — that's the point of the demo switch).
- Knob-off reconcile removes a persisted fake on the next `read()` (any
  `DELETE /backends/fake` can't stick while the knob is on).
- `MASA_MAX_TOOL_ROUNDS=0` would leave the round-1 thinking preamble as the
  answer — a pre-existing agent-loop edge (content+tool_calls sets
  `final_text`), not a fake regression; the default 3 rounds never hit it.
